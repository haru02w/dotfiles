# dotfiles

NixOS + Home Manager configuration built on the [**den**](https://den.denful.dev)
framework using the [Dendritic](https://den.denful.dev/explanation/core-principles/)
pattern.

Every `.nix` file under [`modules/`](./modules) is auto-imported as a flake-parts
module (`outputs = import-tree ./modules` in [`flake.nix`](./flake.nix)). There is
no central import list — drop a file in the right directory and it is picked up.
[`import-tree`](https://github.com/vic/import-tree) only imports `.nix` files and
skips any path containing a `/_` segment, so prefixing a file or directory with
`_` archives/disables a module without deleting it.

> `flake.nix` is auto-generated by [`flake-file`](https://github.com/vic/flake-file).
> Do **not** edit it by hand. Inputs are declared inline in the module that uses
> them (via `flake-file.inputs`) and regenerated with `nix run .#write-flake`.

## Concepts (den in 60 seconds)

| Term | What it is |
|---|---|
| **aspect** | A composable unit of config: `den.aspects.<name>`, bundling `nixos` / `homeManager` modules + `includes` + `provides`. The core building block. |
| **battery** | A reusable aspect provider shipped by den under `den.batteries.*` (e.g. `define-user`, `hostname`, `user-shell`). |
| **class** | A module evaluation domain: `nixos`, `homeManager`, `darwin`, ... |
| **includes** | List of aspect refs / inline modules an aspect depends on (forms a DAG). |
| **provides** | Named sub-aspects for host↔user mutual config (`to-users`, `to-hosts`). |
| **host / user** | Entities registered in `den.hosts.<system>.<name>.users.<user>`. |

An aspect can be split across **many files** — every file that writes
`den.aspects.zephyrus.*` merges into the same `zephyrus` aspect.

## Repository layout

```
modules/
├── default.nix            # den root: defaults, schemas, host registry
├── flake/                 # flake-parts plumbing (dendritic, devshell, formatter, nixpkgs)
├── profiles/              # layered bundles of features (base ⊂ headless ⊂ desktop)
├── features/              # one aspect per concern (git, niri, zsh, sops, ...)
│   ├── hardware/          # driver/boot aspects (nvidia, grub, kvm-amd, ...)
│   └── _old/              # archived modules — `_` prefix makes import-tree skip them
├── configurations/        # per-host config (e.g. zephyrus/) — host aspect + disko + hardware
├── users/                 # per-user aspects (haru02w.nix)
├── packages/              # flake packages built per-system (nvf neovim)
└── tools/                 # extra flake packages/apps (nh host builders, vm runner)
```

Defaults, entity schemas and the host registry live in
[`modules/default.nix`](./modules/default.nix):

```nix
den = {
  default.includes = [ den.batteries.define-user den.batteries.hostname den.batteries.inputs' ];
  schema.user = { classes = lib.mkDefault [ "homeManager" ]; includes = [ den.batteries.mutual-provider ]; };
  hosts.x86_64-linux.zephyrus.users.haru02w = { };
};
```

## Adding a host

1. Create `modules/configurations/<host>/configuration.nix` declaring an aspect
   named after the host:

   ```nix
   { den, ... }:
   {
     den.aspects.<host> = {
       includes = [
         den.aspects.desktop          # pick a profile
       ];
       nixos = { };
       provides.to-users.homeManager = _: { };
     };
   }
   ```

2. Add hardware / disk files in the **same directory** — they all merge into the
   same host aspect (see [`zephyrus/`](./modules/configurations/zephyrus)):
   `hardware-configuration.nix`, `disko.nix`, `<host>-hardware.nix`. Each writes
   `den.aspects.<host>.nixos` and/or `den.aspects.<host>.includes`.

3. Register the host + its user(s) in [`modules/default.nix`](./modules/default.nix):

   ```nix
   den.hosts.x86_64-linux.<host>.users.<user> = { };
   ```

   The host name binds to the aspect of the same name automatically. `class`
   (`nixos`/`darwin`) is auto-detected from `<system>`.

Build it: `nix run .#<host> -- switch` (see [Build & test](#build--test)).

## Adding a user

1. Create `modules/users/<user>.nix`:

   ```nix
   { den, ... }:
   {
     den.aspects.<user> = {
       includes = [
         den.batteries.primary-user        # wheel + networkmanager groups
         den.batteries.host-aspects        # inherit host's homeManager config
         (den.batteries.user-shell "zsh")  # login shell at OS + HM level
       ];
       homeManager = { pkgs, ... }: {
         home.packages = with pkgs; [ neovim ];
       };
       provides.to-hosts.nixos = _: { };
     };
   }
   ```

2. Attach the user to a host in [`modules/default.nix`](./modules/default.nix):
   `den.hosts.<system>.<host>.users.<user> = { };`

Users default to `classes = [ "homeManager" ]` (set in `den.schema.user`).

## Adding a profile

Profiles are just aspects that bundle features via `includes`. They live in
[`modules/profiles/`](./modules/profiles) and layer on each other
(`base` ⊂ `headless` ⊂ `desktop`).

```nix
# modules/profiles/<profile>.nix
{ den, ... }:
{
  den.aspects.<profile> = {
    includes = [
      den.aspects.headless    # build on a lower layer
      den.aspects.<feature>   # pull in features
    ];
    nixos = { pkgs, ... }: { /* profile-wide system config */ };
    homeManager = { pkgs, ... }: { /* profile-wide user config */ };
  };
}
```

Use a profile by including it from a host (or another profile).

## Adding a feature

A feature is one aspect for one concern, in [`modules/features/`](./modules/features).
Put it in `hardware/` if it is a driver/boot concern.

```nix
# modules/features/<feature>.nix
{ den, ... }:
{
  den.aspects.<feature> = {
    nixos = { pkgs, ... }: { /* system-level config */ };
    homeManager = { pkgs, ... }: { /* user-level config */ };
  };
}
```

If the feature needs a new flake input, declare it **inline** so `flake-file`
can pick it up (don't touch `flake.nix`):

```nix
{ inputs, ... }:
{
  flake-file.inputs.<input> = {
    url = "github:owner/repo";
    inputs.nixpkgs.follows = "nixpkgs";
  };
  den.aspects.<feature>.nixos = {
    imports = [ inputs.<input>.nixosModules.default ];
    # ...
  };
}
```

Then add `den.aspects.<feature>` to a profile's (or host's) `includes`.
After editing inputs, run `nix run .#write-flake` to regenerate `flake.nix`.

### Adding packages (to a host/user)

Just write into `home.packages` or `environment.systemPackages` from any aspect:

```nix
den.aspects.<name>.homeManager = { pkgs, ... }: {
  home.packages = with pkgs; [ btop ripgrep ];
};
# or system-wide:
den.aspects.<name>.nixos = { pkgs, ... }: {
  environment.systemPackages = with pkgs; [ git ];
};
```

`allowUnfree = true` is already set globally in
[`modules/flake/nixpkgs.nix`](./modules/flake/nixpkgs.nix), so unfree packages
(`discord`, `vesktop`, ...) just go straight in the package list — see
[`desktop.nix`](./modules/profiles/desktop.nix). For **insecure** packages, or
if you later tighten `allowUnfree`, reach for the batteries:

```nix
includes = [
  (den.batteries.unfree [ "discord" ])
  (den.batteries.insecure [ "openssl-1.1.1w" ])
];
```

## Adding a flake package

Packages built per-system go in [`modules/packages/`](./modules/packages) or
[`modules/tools/`](./modules/tools) via `perSystem.packages`:

```nix
# modules/tools/<name>.nix
{
  perSystem = { pkgs, ... }: {
    packages.<name> = pkgs.writeShellApplication {
      name = "<name>";
      text = "echo hello";
    };
  };
}
```

The [`nvf`](./modules/packages/nvf) Neovim package shows the modular pattern: a
`perSystem` option (`nvf.module`) is merged across every plugin file, then fed
to `neovimConfiguration` in [`default.nix`](./modules/packages/nvf/default.nix).
Add a plugin by dropping a file in `modules/packages/nvf/plugins/` that writes
`perSystem.nvf.module.config.vim.<...>`.

Current flake packages: `nvf`, `vm`, `zephyrus` (nh host builder),
`write-flake` / `write-inputs` / `write-lock` (flake-file generators).

## Secrets

Secrets are managed with [sops-nix](https://github.com/Mic92/sops-nix) (age key
at `~/.config/sops/age/keys.txt`). The `sops` feature
([`modules/features/sops.nix`](./modules/features/sops.nix)) wires
[`secrets/secrets.yaml`](./secrets) into both NixOS and Home Manager. Edit
secrets from the dev shell:

```console
nix develop          # provides sops, age, ssh-to-age
sops secrets/secrets.yaml
```

## Build & test

```console
# build / switch a host (uses nh under the hood)
nix run .#zephyrus              # default action: build
nix run .#zephyrus -- switch    # apply

# spin up a throwaway VM of the host to test changes without rebooting
nix run .#vm

# regenerate flake.nix / flake.lock after changing inputs
nix run .#write-flake
nix flake update den            # bump the den framework

# format
nix fmt                         # nixfmt via treefmt-nix
```

A dev shell with `sops`, `age`, `ssh-to-age`, `claude-code`, `opencode`, `nodejs` is available
via `nix develop` (auto-loaded by [direnv](./.envrc)).
